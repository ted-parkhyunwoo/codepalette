어려웠던점 / 극복과정
1. 간단할 줄 알고 현재까지 코드 작성중 위젯의 분류를 주석으로 표기하지 않아 특정 위젯이 어떤 역할을 하는지 찾는게 불편했습니다. 결국 처음부터 하나씩 다시 지정했습니다.
2. Icon을 사용한 IconButton의 icon 지정과 style 지정 방법등을 찾느라 시간이 걸렸습니다. IDEA나 vscode의 힌트를 통해 control shift를 통해 어떤것을 사용할 수 있는지 살피고, 변수에 커서를 올려 타입을 확인하는것이 유용했습니다.
3. vscode 의 flutter hot reload의 단축키 지정방법을 몰라 조금 귀찮았습니다. 끝날 때 까지 이것은 찾아보지 않고 빠른 시간 안에 코드를 작성하는것에 집중했습니다. 다음 프로젝트를 진입하기 전에 단축키 지정을 해결해볼 계획입니다.
4. 다양한 플랫폼에서의 활용을 위한 padding, margin,  위치 배정과 scroll 가능 여부를 지정하는것이 번거로웠습니다. 이것은 앱개발 뿐만 아니라 웹 프론트엔드에서도 많은 개발자들을 괴롭히는 것으로 알고 있습니다. 가로모드, 세로모드에 따른 변화를 줄 것인지 여부와, 과도하게 작은 디스플레이는 표현하지 않을지에 대한 여부도 개발단계 초기 설정에 필요할 것 같습니다.
5. 시간 내 완성 하는것이 쉽지 않았습니다. 중요한 일을 내버려 둔채 조금더 아름답게 만들기 위해 시간이 많이 지났습니다. 앞으로 가능하면 위젯을 배치할 것인지부터 생각하고 정렬과 로직정도만 최우선으로 신경 쓰는 작업 우선순위를 정하는것이 좋을 것 같습니다. UI 개선은 로직과 디버깅 완료 후 시간이 여유로운 이후에 할 일이라 생각됩니다.


사용한 flutter / dart  의 기술
1. 자주 사용할 위젯이나 속성을 가능하면 final 지역변수 처리 하고, 그것의 재활용 비율이 빈번하다면 class로 분리했습니다.
2. IDE로부터 오버헤드 때문에 Container 사용을 자제하라는 제안을 받았지만, 이것만큼 다양한 역할을 할 수 있는 위젯은 많지 않은것 같아 코드가 복잡해지는 것을 피하기 위해 반드시 필요한 부분은 검토 후 적극적으로 사용하였습니다.
3. 다른 GUI용 개발처럼 while문같은 형식과는 다르게, flutter의 stateless한 widget에 생성자 매개변수로 함수포인터를 전달하고, stateful한 widget은 오직 하나로만 setstate 컨트롤 한다는 개념이 빠른 개발에 도움이 됐고, 이 방법이 너무 편리했습니다.
